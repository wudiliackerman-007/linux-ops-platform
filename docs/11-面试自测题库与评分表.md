# 11 面试自测题库（带评分表）

> 用法：**先不看答案**，用手机录音回答，再回来对照评分要点打分。
> 每题满分 5 分，答完给自己打分，低于 3 分的题抄到错题本上，第二天重答。
>
> 这份和 `docs/05-面试30题.md` 的区别：05 是"知识点 + 应答"，这份是**打分卡**——
> 写清了什么是红线（说出来就掉分）、什么是加分项（说出来面试官会眼睛一亮）。
> 所有数字都是本机实测值（见 `docs/09-实机验证报告.md`）。

## 第 1 轮：讲项目（5 题，考结构）

### Q1. 用两三分钟介绍这个项目：解决什么问题、架构、你做了什么。

| 打分 | 标准 |
| --- | --- |
| 5 分 | 先给结论（"一台机器上可发布、可监控、可回滚、可恢复的环境"）→ 链路（用户 → Nginx → gunicorn/FastAPI → MySQL/Redis）→ "我做的"三件事（部署脚本、监控告警、故障演练）→ 至少 2 个数字 |
| 3 分 | 说了组件但没讲顺序，或者全程"我们" |
| 1 分 | 从"我用了 Docker"开始（本项目不用 Docker，说了就是编） |
| 红线 | 讲不清请求经过哪些组件；把"项目有的"说成"我做的" |

**必须能脱口而出的链路**：

```
浏览器 --443--> Nginx（TLS、限流、JSON 日志）
                └─ proxy_pass --> gunicorn :8000（FastAPI，8 worker = min(2×4核+1, 8)）
                                    ├─ Redis :6379（缓存短码，挂了自动降级直连 MySQL）
                                    └─ MySQL :3306（links 表，仅监听 127.0.0.1）
Prometheus :9090 每 15s 抓 7 个目标（含应用 /metrics），规则算完推 Alertmanager :9093，
Alertmanager 按 severity 分组后 webhook 到 :5001，落地 /var/log/ops-platform/alerts.log
```

## 第 2 轮：技术细节（7 题，考深度）

### Q6. Prometheus 是拉还是推？为什么？

> 5 分：拉（pull）。理由至少两条：**服务不用关心监控地址**（配置在监控端）、**抓不到就是 down**（天然健康判断）；再补一句项目里的实践：node_exporter 的 textfile collector 让"跑完就退出的脚本"（备份、巡检、日报）也能被采集。

**红线**：说"Prometheus 是推的"。

### Q7. `rate()` 和 `increase()` 有什么区别？`histogram_quantile()` 为什么需要 `sum by (le)`？

> 5 分：`rate` 是每秒速率、`increase` 是区间总量（都是对 counter 用，且区间内至少两个点）；`histogram_quantile` 要先按 `le` 聚合再算分位，直接对实例算会得到每个实例的分位，不是全局分位。
> 加分：本项目 P95 面板就是 `histogram_quantile(0.95, sum by (le) (rate(..._bucket[1h])))`。

### Q8. 你在项目里遇到过哪些"看起来正常其实错了"的问题？

**这题是本项目最有价值的一题，至少准备两个：**

| 例子 | 要点 |
| --- | --- |
| 看板 JSON 坏了但页面正常 | Grafana 的 file provisioner 解析失败会**静默保留数据库里的旧版本**，页面照常显示。是 CI 里 `json.load` 抓出来的。结论：**看到的不等于部署的** |
| 备份成功却报 `BackupStale` | 指标约定 1=成功，脚本写的是退出码（0=成功）。结论：**告警不准比没有告警更糟**，会让人开始忽略告警 |

> 5 分：讲清"现象 → 根因 → 怎么发现的 → 怎么改"；3 分：只说"遇到过一个 bug，后来改好了"。

### Q9. 应用崩溃后 4 秒自动拉起，靠的是什么？为什么不用 nohup 或 supervisor？

> 5 分：systemd 的 `Restart=always` + `RestartSec`，加上 gunicorn 自己也有 worker 守护；不用 nohup 是因为**没有启动顺序、没有依赖、没有日志轮转、没有失败重启策略**，机器重启就没了；supervisor 能做到但 systemd 已经内置，不用多一个守护进程。
> 加分：说出 `ProtectSystem=strict`、`NoNewPrivileges=true`、journald 500M 上限这些加固项。

### Q10. 发布为什么要 `releases/<时间戳>` + `current` 软链？直接覆盖代码不行吗？

> 5 分：三个理由——**原子切换**（`ln -sfn` 是原子的，不会读到半个文件）、**秒级回滚**（切回上一个软链）、**可审计**（`readlink` 就知道线上是哪个版本）；再补：发布脚本自带健康检查，失败自动切回上一版，保留最近 5 个版本。

### Q11. 数据库挂了，接口应该返回什么？为什么不是 500？

> 5 分：**503**。500 是"服务代码出错"，503 是"暂时不可用"——后者告诉调用方和负载均衡"可以重试/摘流量"，也告诉值班的"查依赖，别查代码"。
> 本项目做法：`_db_call()` 捕获异常转 503，坏连接标记 `broken=True` 直接关闭不回池（否则连接池里全是坏连接）。

### Q12. Redis 挂了为什么业务还能用？降级怎么做的？

> 5 分：缓存只是加速层，读不到就去 MySQL 回源；关键是**降级要自动、要可观测**：本项目 `opslink_dependency_up{redis}=0` 是一个指标，`AppCacheDegraded` 告警会响，但业务不报错。实测停 Redis 300 秒，20 次请求异常 0 次。

## 第 3 轮：故障场景（6 题，考动手）

> 这一轮面试官会故意给模糊条件，你要**先问清影响面，再动手**。上来就敲命令是减分的。

### Q13. 用户说网站打不开了，你怎么排查？

5 分的顺序是**从外到内、从粗到细**，不是背命令：

1. 先确认是"全站"还是"部分"：`curl -sk -o /dev/null -w '%{http_code}' https://<IP>/health/ready`
2. 看是不是 DNS/TLS 层：`curl -v`、证书过期了吗
3. Nginx 通不通：`systemctl status nginx`、`tail /var/log/nginx/opslink_access.log`（JSON 日志，看 status 和 request_time）
4. 后端通不通：`curl 127.0.0.1:8000/health/live`、`ss -lntp | grep 8000`
5. 依赖通不通：`mysqladmin ping`、`redis-cli -a 密码 ping`
6. 最近改了什么：`./scripts/rollback.sh --list`、`journalctl --since '30 min ago'`

**加分**：第一步就说"我先确认影响面，是全站还是只有写接口"，并打开 Grafana 看 QPS 和 5xx 曲线。

### Q14. 磁盘满了怎么办？

> 5 分：先 `df -h` 定位是哪个分区 → `du -sh /* | sort -h` 找大头 → 常见元凶：**日志、备份、MySQL binlog、/tmp**；止血手段按代价排序：清可再生的（日志轮转、旧备份）、扩盘、挪数据；最后改配置（logrotate 保留策略、备份保留天数）+ 加告警。
> 本项目对应：`HostDiskUsageHigh`（>80%）、`HostDiskWillFull`（用 `predict_linear` 预测 4 小时内写满），演练脚本 `ops/chaos/02_disk_fill.sh 60`。
> **红线**：说"直接 rm -rf /var/log/*"（可能删掉正在写的日志、也可能删错）。

### Q15. 数据库连接数打满了，你怎么处理？

> 5 分：先看是谁占的（`SHOW PROCESSLIST` / `performance_schema`）→ 分清是**慢查询堆积**还是**应用连接池泄漏**→ 止血（kill 长事务、临时调大 `max_connections`）→ 根因（加索引、改连接池上限、加超时）。
> 本项目：`MySQLHighConnections`（>80%）、`MySQLSlowQueries` 两条告警；MySQL 只监听 127.0.0.1，连接池 `maxsize` 有上限。

### Q16. 备份怎么保证能用？

> 5 分：**备份不做恢复演练等于没有备份**。本项目三层：① 备份后 `gzip -t` + 检查 `Dump completed` + 大小 >1KB；② 每周日自动把最新备份恢复到临时库 `opslink_restore_check` 并**比对行数**；③ 备份成功时间写成指标 `ops_backup_last_success_timestamp_seconds`，超过 2 天没成功就 `BackupStale` 告警。

### Q17. 告警太多、大家都开始忽略了，怎么治？

> 5 分：先删"不可行动"的告警 → 分级（critical/warning）→ 分组（同一次故障只发一条）→ 抑制（`HostDown` 抑制同实例所有 warning；`AppDown` 抑制错误率）→ 加 `for` 让瞬时抖动不告警 → 定期复盘"响过的告警里有几条真需要人动手"。
> 本项目：Alertmanager `group_wait` critical 10s / warning 2m，`repeat_interval` 1h / 6h，两条 inhibit 规则。

### Q18. 监控系统自己挂了怎么办？

> 5 分：这是"谁监控监控"的经典问题。本项目做法：① 巡检脚本每 5 分钟**独立**跑一遍 HTTP 探针（不依赖 Prometheus）；② 日报每天 08:00 生成，`ReportStale` 告警监控"日报是否还在生成"；③ 生产环境应该再加一层外部黑盒探活（不同机房/云厂商）。

## 第 4 轮：反问与边界（3 题，考成熟度）

### Q19. 你觉得这个项目最大的不足是什么？

> 5 分：说得具体、说得诚实、说得有下一步：
> "单机，没有高可用——机器挂了就全挂；告警只到本地 webhook，没有真实通知渠道和值班轮换；没做过真正的容量规划，压测只有 900 个请求的量级；没有灰度发布。下一步我会先补通知渠道和多机部署，再考虑 K8s。"

**红线**：说"没有不足"（不成熟）或者把不足说成"因为时间不够"（听起来像借口）。

### Q20. 你没有任何生产经验，我们为什么要你？

> 5 分：不辩解，用**可验证的事实**替代经验：这套环境是我自己从裸机装的、坏了 8 次都是我自己修的（`docs/09` 有记录）、我会写脚本让重复劳动自动化、我能把一次故障从告警讲到复盘。然后补一句"生产环境的差异我清楚：规模、多人协作、变更流程，这些我需要人带"。

### Q21. 你有什么想问我的？

**必须准备 3 个，问出"你真的在想这份工作"的感觉：**

- 团队现在运维多少台机器？主要痛点是稳定性还是效率？
- 值班是怎么轮的？新人上 on-call 前会有带教期吗？
- 实习生前三个月一般做什么？有没有机会参与变更和故障复盘？

**红线**："你们加班多吗""有转正机会吗"放最后问，或者干脆不问——第一轮面试问这些会显得你只关心自己。

## 附 2：共享屏幕演示脚本（3 分钟，面试官说"给我看看"时用）

按这个顺序切窗口，每一步一句话，不要念配置：

1. **Grafana 看板**（30 秒）："这是总览，上面 4 个是关键指标，下面是资源、QPS、延迟、依赖可用性。"
2. **Prometheus `/targets`**（20 秒）："7 个抓取目标，全 up；这是它怎么发现问题的——抓不到就是 down。"
3. **`/alerts` 或 Alertmanager**（30 秒）："这是当前活跃告警和抑制关系。"
4. **终端跑巡检**（40 秒）：`sudo /opt/ops-platform/bin/healthcheck.sh`，"20 项，从依赖到端到端建码跳转。"
5. **日报**（20 秒）：`sudo cat /var/log/ops-platform/report/latest.txt`，"每天 08:00 自动生成，交接班看这个。"
6. **发布/回滚**（40 秒）：`sudo ./scripts/rollback.sh --list` 和 `readlink -f /opt/ops-platform/current`，"发布是新建目录切软链，回滚就是切回去。"

**红线**：演示时现场敲一条没跑过的命令，然后卡住——提前 10 分钟把这几条都跑一遍。
