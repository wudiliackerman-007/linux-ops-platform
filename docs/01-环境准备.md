# 01 环境准备

> 目标：在 Windows 主机上用 VMware 跑出一台能上网、能用 SSH 登录的 Ubuntu 22.04 虚拟机。
> 全程约 40 分钟，其中 20 分钟是等待安装。
>
> **读者**：准备自己装一台实验机的人。**完成后得到**：一台能 SSH 登录、能上网、能打快照回滚的 Ubuntu 22.04。

## 0. 资源规划

| 项 | 建议值 | 说明 |
|----|--------|------|
| CPU | 4 核 | 少了 gunicorn 多 worker + Prometheus 会卡 |
| 内存 | 6 GB | 4 GB 能跑，但 Grafana 打开会明显变慢 |
| 磁盘 | 60 GB 精简置备 | MySQL 数据 + Prometheus TSDB(15 天) + 镜像下载 |
| 网络 | NAT | 虚拟机共享主机网络，能上网，主机可 SSH 进去 |
| 主机剩余空间 | ≥ 15 GB | ISO 2.1 GB + 虚拟机磁盘增长 |

## 1. 安装 VMware（已装可跳过）

VMware Workstation 17.x（Player/Pro 均可）。装完确认两个服务在跑：

```powershell
# Windows PowerShell（管理员）
Get-Service "VMware NAT Service", "VMnetDHCP" | Format-Table Name, Status
```

如果没启动：`Start-Service VMnetDHCP; Start-Service "VMware NAT Service"`。

> 国内网络下不建议下载 Docker Desktop / WSL 发行版，本方案完全不需要。

## 2. 下载 Ubuntu 22.04 Server

官方源慢，用国内镜像（任选其一）：

```text
https://mirrors.tuna.tsinghua.edu.cn/ubuntu-releases/22.04/ubuntu-22.04.5-live-server-amd64.iso
https://mirrors.aliyun.com/ubuntu-releases/22.04/ubuntu-22.04.5-live-server-amd64.iso
```

文件约 2.0 GB。下载后校验（强烈建议，坏包会导致装到一半报错）：

```powershell
# Windows PowerShell
Get-FileHash .\ubuntu-22.04.5-live-server-amd64.iso -Algorithm SHA256
```

与镜像站同目录下 `SHA256SUMS` 里的值对比。本项目验证过的正确值：

```
9bc6028870aef3f74f4e16b900008179e78b130e6b0b9a140635434a46aa98b0
```

## 3. 创建虚拟机

图形化安装（推荐第一次手动装一次，理解过程）：

1. VMware → 新建虚拟机 → **自定义(高级)**
2. 稍后安装操作系统 → Linux → **Ubuntu 64 位**
3. 位置选空间大的盘，例：`E:\vm\ubuntu-ops`
4. 磁盘 **60 GB**，选"将虚拟磁盘拆分成多个文件"
5. 自定义硬件：内存 6144 MB、处理器 4、网络适配器 **NAT**、声卡/打印机移除
6. 挂载 ISO 后启动

安装过程中的关键选项：

| 步骤 | 选择 |
|------|------|
| 语言 | English（避免中文路径和日志编码问题，也顺便练英语） |
| 键盘 | 默认 |
| 安装类型 | **Ubuntu Server**（不要 minimized） |
| 网络 | 默认 DHCP（NAT 网段一般是 `192.168.x.0/24`） |
| 代理 | 留空 |
| 镜像源 | `https://mirrors.aliyun.com/ubuntu`（安装时就能加速） |
| 磁盘 | **Use an entire disk**，不启用 LVM 也行（启用更贴近生产） |
| 用户 | 用户名 `ops`（或你自己的），**记住密码** |
| SSH | **勾选 Install OpenSSH server** |
| 预置软件 | 什么都不选（snap 的 docker 不要选） |

装完重启，用主机 PowerShell 验证：

```powershell
ssh ops@192.168.x.x
```

## 4. 装完立刻做的三件事

```bash
# 1) 更新系统（换成阿里源后很快）
sudo sed -i 's|http://.*archive.ubuntu.com|https://mirrors.aliyun.com|; s|http://security.ubuntu.com|https://mirrors.aliyun.com|' /etc/apt/sources.list
sudo apt update && sudo apt -y upgrade

# 2) 拍快照（VMware 菜单：虚拟机 → 快照 → 拍摄快照，名字写 "clean-install"）
#    后面任何一步搞坏了，30 秒回到这里

# 3) 记下 IP 和主机名
hostname -I; hostnamectl
```

**快照是这套流程的生命线**：`clean-install` → 装完中间件后再拍一个 `after-middleware`。

## 5. 配置免密 SSH（推荐）

主机上（Windows 已自带 OpenSSH）：

```powershell
ssh-keygen -t ed25519 -C "ops-lab"          # 一路回车，默认 C:\Users\<你>\.ssh\id_ed25519
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh ops@192.168.x.x "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 700 ~/.ssh && chmod 600 ~/.ssh/authorized_keys"
ssh ops@192.168.x.x "echo ok"
```

`deploy/bootstrap.sh` 只有在 `authorized_keys` 存在时才会关闭密码登录 —— 所以**先配免密，再跑脚本**，否则会被锁在外面（脚本刻意做了这个保护）。

## 6. 克隆仓库

```bash
sudo apt install -y git
sudo mkdir -p /opt/ops-platform
sudo git clone git@github.com:<你的用户名>/linux-ops-platform.git /opt/ops-platform/repo
```

GitHub 在国内 SSH 22 端口常被阻断。仓库如果拉不下来，用 **443 端口**：

```bash
# ~/.ssh/config
Host github.com
    HostName ssh.github.com
    Port 443
    User git
```

或直接用 Gitee 镜像仓库（本项目同时推了两个远端）。

## 7. 网络自检（决定后面能不能装监控）

```bash
for u in https://mirrors.aliyun.com/ubuntu/ \
         https://mirrors.tuna.tsinghua.edu.cn/grafana/ \
         https://pypi.tuna.tsinghua.edu.cn/simple/ \
         https://gh-proxy.com/ ; do
  printf '%-55s ' "$u"; curl -s -o /dev/null -w '%{http_code}\n' --max-time 10 "$u" || echo FAIL
done
```

> 提示：`mirrors.huaweicloud.com` 看起来有 Prometheus 目录，但对不存在的文件会返回 **200 + HTML 错误页**，直接 `curl` 下来的"tar.gz"其实是网页。本项目因此优先走 `gh-proxy.com`，并在 `deploy/lib/common.sh` 的 `download()` 里做了内容校验（首字节是 `<` 或 gzip 魔数不对就判失败）。

四个都应是 `200/301/302`。Docker Hub 不通没关系，本方案不用它。

## 8. 常见问题

| 现象 | 原因 | 解决 |
|------|------|------|
| 虚拟机没网 | NAT 服务没起 / 网卡没连 | `Get-Service` 检查；VM 设置里勾"已连接" |
| `apt update` 卡在 `archive.ubuntu.com` | 没换源 | 执行第 4 节第一条命令 |
| 安装时"无法下载安装程序" | 镜像源不通 | 安装界面换 `mirrors.aliyun.com` 或 `mirrors.tuna` |
| 磁盘只剩几 G | 默认 20 GB | 关机后 `vmware-vdiskmanager -x 60GB disk.vmdk` 扩容，再在系统里扩分区 |
| SSH 连不上 | 防火墙/没装 openssh | `sudo ufw status`、`systemctl status ssh` |
| 时间不对导致告警误报 | 时区/chrony | `timedatectl set-timezone Asia/Shanghai`、`systemctl status chrony` |

## 附：本项目自动化安装记录（可选）

本项目也用 Ubuntu Server 的 autoinstall（cloud-init）无人值守方式装过，脚本思路如下（仅作记录，正常用第 3 节的图形安装即可）：

1. 解压 ISO 到某个临时目录（例如 `/tmp/iso-tree`）
2. 根目录放 `autoinstall.yaml`（`identity` / `storage` / `late-commands` 里写好用户、SSH key）
3. 改 `boot/grub/grub.cfg` 的 `linux` 行追加 `autoinstall ds=nocloud;s=/cdrom/nocloud/ console=ttyS0,115200n8`，`timeout=1`
4. `mkisofs -b boot/grub/i386-pc/eltorito.img -c boot.cat -no-emul-boot -boot-load-size 4 -boot-info-table -J -joliet-long -R -o auto.iso tree/`
5. `vmware-vdiskmanager -c -s 60GB -a lsilogic -t 0 disk.vmdk` 造盘，手写 `.vmx`（`guestOS=ubuntu-64`、`memsize=6144`、`numvcpus=4`、`ethernet0.connectionType=nat`）
6. `vmrun start ...`，从虚拟机串口日志 `console.log` 观察安装进度

结论：自动化只适合"要反复重建 N 次"的场景；第一次学，手动装一遍更有价值（知道每一步在干什么）。
