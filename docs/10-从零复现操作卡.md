# 10 从零复现操作卡（打印出来照着做）

> 目标：一台干净的 Ubuntu 22.04，从装系统到「监控告警全部跑起来」，**90 分钟内**走完一遍。
> 每一步都写了「你该看到什么」，看不到就是没走通，先查第 7 节的卡点表，别往下做。
>
> 这份操作卡和 `docs/01`、`docs/02` 的关系：01/02 讲**为什么**，这份只讲**怎么做、看到什么算过**。

---

## 0. 开始之前，确认三件事

| 检查 | 怎么做 | 要求 |
| --- | --- | --- |
| 宿主机内存 | 任务管理器 → 性能 | 至少 8 GB 空闲（虚拟机要 6 GB） |
| 宿主机磁盘 | 看 E 盘剩余 | 至少 30 GB（虚拟机实际占 12 GB 左右） |
| 能上网 | 浏览器打开 mirrors.aliyun.com | 打不开就先解决网络，后面全靠它 |

**建议先打快照**：装完系统打一个，一键部署跑完再打一个。演练搞坏了回滚 30 秒，比修 2 小时划算。

---

## 1. 装 Ubuntu 22.04（约 20 分钟）

1. VMware → 新建虚拟机 → 自定义 → 稍后安装操作系统。
2. 客户机操作系统：Linux / Ubuntu 64 位。
3. 名称 `ops-lab`，位置选空间大的盘（示例 `E:\vms\ops-lab`）。
4. 处理器 2 核（有 4 核更好）、内存 **6144 MB**（低于 4 GB 后面 MySQL + Prometheus 会吃紧）。
5. 网络：**NAT**（默认就是）。
6. 磁盘：**60 GB**，存储为单个文件。
7. 编辑虚拟机设置 → CD/DVD → 使用 ISO 映像 → `ubuntu-22.04.5-live-server-amd64.iso` → 启动。
8. 安装过程按这个选：
   - 语言 English（中文会有终端编码坑）
   - 网络：默认 DHCP 就行（后面 bootstrap 会把时区、源配好）
   - 存储：**Use an entire disk**（不搞 LVM 手动分区，练习阶段没必要）
   - 用户名：`ops`，机器名 `ops-lab`，**密码记下来**
   - 勾选 **Install OpenSSH server**
   - 不要勾任何 snap 附加包（Docker 之类后面用不到）
9. 装完重启，登录，确认：

```bash
lsb_release -a          # 期望：Ubuntu 22.04.5 LTS
ip -4 addr show | grep inet    # 记下 IP，下面用 <IP> 代替
free -h                 # 期望：内存约 5.8Gi
df -h /                 # 期望：根分区约 59G
```

> 装不上的常见原因：CPU 虚拟化没开（BIOS 里 Intel VT-x / AMD-V）、Hyper-V 冲突
> （`bcdedit /set hypervisorlaunchtype off` 后重启）、ISO 下载不完整（核对 SHA256）。

## 2. 把代码放进虚拟机（约 5 分钟）

三种方式任选：

**A. 直接 scp（Windows 自带 scp）**

```powershell
# 在 Windows PowerShell 里执行，<IP> 换成虚拟机 IP
scp -r E:\projects\linux-ops-platform ops@<IP>:/home/ops/
```

**B. 虚拟机能上网就 git clone**（推到 GitHub 之后）

```bash
sudo apt-get update && sudo apt-get install -y git
git clone https://github.com/<你的用户名>/linux-ops-platform.git
```

**C. 用 VMware 共享文件夹 / WinSCP**（图形化，适合不熟命令行的阶段）

放好之后确认：

```bash
cd ~/linux-ops-platform && ls
# 期望看到：README.md app conf deploy docs monitoring ops scripts .github
```

## 3. 一键部署（约 25 分钟）

```bash
cd ~/linux-ops-platform
sudo ./deploy/all_in_one.sh
```

它会依次跑：`bootstrap` → `install_middleware` → `install_app` → `install_nginx` →
`install_monitoring` → `install_timers`。

**过程中该看到什么**

| 阶段 | 关键输出 | 大概耗时 |
| --- | --- | --- |
| bootstrap | `已关闭密码登录（仅保留密钥）`、`已配置 swap` | 3–5 分钟（装包最慢） |
| middleware | `MySQL 已就绪`、`Redis 已就绪`、`已写入 app.env` | 3–4 分钟 |
| app | `冒烟测试通过`、`当前版本 -> releases/<时间戳>` | 1–2 分钟 |
| nginx | `80 -> 301`、`443 -> 200` | 1 分钟 |
| monitoring | 5 个二进制 + Grafana 装好，7 个 target 表格 | 5–8 分钟（要下载约 160 MB） |
| timers | `systemctl list-timers` 四行 | 30 秒 |

结束时最后几行应该是：

```
==> 全部完成，耗时 xx 分 xx 秒
```

> **中途失败了怎么办**：脚本是幂等的，修完直接重跑同一条命令，不会重复换密码、不会重装已装的包。
> 日志在 `/var/log/ops-platform/install-<时间戳>.log`，报错行往前 20 行一般就能看出原因。

## 4. 验收五连（约 5 分钟，必须全过）

```bash
# 1. 巡检 20 项，只要有一项失败退出码就不是 0
sudo /opt/ops-platform/bin/healthcheck.sh
echo "exit=$?"                       # 期望：exit=0

# 2. 七个抓取目标全 up
curl -s http://127.0.0.1:9090/api/v1/targets?state=active \
  | grep -o '"health":"[a-z]*"' | sort | uniq -c
# 期望：7 个 "health":"up"

# 3. 告警规则加载了几条
curl -s http://127.0.0.1:9090/api/v1/rules | grep -o '"name":"[A-Za-z]*"' | wc -l
# 期望：>= 27（一共 28 条，TargetDown 等名字带大写）

# 4. 业务真的能用（走 HTTPS 建一条再跳一下）
curl -sk -X POST https://127.0.0.1/api/shorten \
  -H 'Content-Type: application/json' -d '{"url":"https://example.com"}'
# 期望：{"code":"xxxxxxx","short_url":"https://.../xxxxxxx"}
curl -sk -o /dev/null -w '%{http_code}\n' https://127.0.0.1/<上面返回的 code>
# 期望：302

# 5. 日报能生成
sudo systemctl start ops-report.service
sudo cat /var/log/ops-platform/report/latest.txt
# 期望：一句话结论是"全部服务正常、无活跃告警、最近一次巡检通过。"
```

五条全过，这套环境就算部署成功了。

## 5. 六个演练，每个 5–10 分钟

```bash
cd ~/linux-ops-platform
sudo bash ops/chaos/04_app_down.sh crash     # 应用崩溃：看 systemd 几秒拉起
sudo bash ops/chaos/05_redis_down.sh 120     # 缓存挂：业务应该完全不受影响
sudo bash ops/chaos/03_mysql_down.sh 120     # 数据库挂：探针 503，告警
sudo bash ops/chaos/01_cpu_spike.sh 180      # CPU 打满：看 Grafana 曲线 + 告警
sudo bash ops/chaos/06_network_delay.sh 200 30
sudo bash ops/chaos/02_disk_fill.sh 60       # 磁盘写满：注意参数是目标百分比
```

演练时**同时开三个窗口**（这是面试要讲的重点）：

```bash
# 窗口 1：看告警进来
sudo tail -f /var/log/ops-platform/alerts.log
# 窗口 2：看服务状态
watch -n 2 'systemctl is-active opslink mysql redis-server | tr "\n" " "'
# 窗口 3：浏览器开着 Grafana 看板
# http://<IP>:3000  admin / sudo grep GRAFANA_ADMIN_PASSWORD /etc/ops-platform/platform.env
```

每个演练完，把「告警几分钟进来、业务表现、多久恢复」记到 `docs/04-故障演练记录.md`。

## 7. 卡点表（按症状查）

| 症状 | 最可能的原因 | 先跑什么 |
| --- | --- | --- |
| `apt-get update` 卡住或 404 | 源没换成国内 | `grep -r mirrors /etc/apt/sources.list*` |
| `pip install` 超时 | 没走清华源 | `cat /etc/pip.conf` |
| 应用起不来，`systemctl status opslink` 是 `failed` | 依赖没装全 / app.env 缺变量 | `sudo journalctl -u opslink -n 50` |
| 打开 443 报证书错误 | **自签证书，正常现象** | 浏览器点"继续访问"，或用 `curl -k` |
| `502 Bad Gateway` | 后端没起来或端口不对 | `curl -s 127.0.0.1:8000/health/live`、`ss -lntp \| grep 8000` |
| `curl: (7) Failed to connect` 到 9090/3000 | 服务没起 / ufw 挡了 | `systemctl status prometheus`、`sudo ufw status` |
| Grafana 看板空白或 "No data" | 数据源没 provision / 时间范围不对 | 右上角时间选 `Last 15 minutes`；`curl 127.0.0.1:9090/-/ready` |
| 看板改了不生效 | provisioner 解析失败会**静默用旧版本** | `sudo journalctl -u grafana-server \| grep -i provision` |
| `/metrics` 404 | 兜底路由抢了路径（老版本代码） | `curl -s 127.0.0.1:8000/metrics \| head` |
| 备份没生成 | 定时器没装 / 磁盘满 | `systemctl list-timers 'ops-*'`、`df -h /data` |
| MySQL 连不上 | 只监听 127.0.0.1（设计如此） | `ss -lntp \| grep 3306` |
| 下载监控二进制失败 | gh-proxy 挂了（它确实会挂） | 手动下载后放 `/tmp/ops-dl/`，脚本会复用 |
| 重跑脚本报"已存在" | 一般不用管，脚本幂等 | 看日志里有没有 `[ERROR]` |

> 判断标准：**`[ERROR]` 才是错，`[WARN]`/`[SKIP]` 一般可以放过**。
